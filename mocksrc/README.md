# mocksrc - Source Code Compilation and Linking Center (Under Development)

**Other Language Versions: [English](./README.md), [中文](./README_zh.md).**

**Status:** Under Development

## Overview

The `mocksrc` directory serves as the central location within the ArceOS project for **unified storage of application source code compilation and linking scripts**.

It provides a set of tools and scripts that allow developers to directly compile and link executable files from application source code, suitable for the ArceOS `loader_lib` environment (including both static and dynamic linking to `mocklibc`).

This directory forms a clear division of labor with the `batch_apps` and `uni_apps` (formerly `mockc_apps`) directories:

* **`mocksrc`**: Responsible for **compiling and linking** application source code to generate executable files.
* **`batch_apps` and `uni_apps`**: Responsible for **packaging** the executable files generated by `mocksrc` into `apps.bin` application packages for loading by `loader_lib`.

## Directory Structure

* `link.ld`: Basic RISC-V linker script used to control the memory layout of applications.
* `Makefile`: Build script used to automate the compilation and linking process.
* `config.mk`: Configuration file used to define toolchain paths (currently primarily supporting musl), common compilation options, and other global settings.

**Note:** The `apps/` subdirectory and other subdirectories and files within the `mocksrc` directory are currently mainly used to store previous test cases and are not essential parts of the current build process. Application compilation and linking are typically performed in the `mocksrc` root directory using the `Makefile`.

## Usage

In the `mocksrc` directory, you can use the `make` command to compile and link applications. You need to specify the following parameters:

* **`BATCH_APPS`**: Specifies the location within the `batch_apps` directory where the compiled executable file will be moved for packaging.
* **`UNI_APPS`**: Specifies the location within the `uni_apps` directory where the compiled executable file will be moved for packaging.
* **`OUTFILE`**: Specifies the name of the output executable file (without extension).
* **`DIR`**: Specifies the name of the subdirectory within the current directory that contains the application's source code.
* **`TYPE`**: Specifies the compilation type, which can be `static` (statically linked to `mocklibc`) or `dynamic` (dynamically linked to `mocklibc`, if supported).

**Basic Compilation Command Example:**

```bash
make TYPE=<static|dynamic> DIR=<app_source_dir> OUTFILE=<output_name>
